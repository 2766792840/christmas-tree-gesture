# 手势交互：One Euro + 统一状态机（V3-P1c）

V2 的手势链路是「MediaPipe 出 label → 数 4 帧稳定 → 直接发命令」。问题有三个：
手指过渡帧会来回切、掌心坐标抖动直接进旋转速度、手离开画面再回来时旧状态还在。
这一版把「滤波 / 去抖 / 状态」抽成一个独立控制器，引擎只负责调用。

## 链路

```
HandLandmarker（约 18 Hz）
  → analyze()            原始 label / conf / 掌心 / 捏合距离 / 掌宽
  → GestureController    One Euro 滤波 + 迟滞 + 候选保持 + 冷却 + 断手重置
  → applyHands()         旋转、缩放、形态、许愿、画笔
```

模块边界：

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `src/core/oneEuro.ts` | 一维 One Euro 滤波器，纯数值 | 无 |
| `src/core/gestureController.ts` | 滤波组合 + 状态机 + 置信度策略 | 只依赖 oneEuro |
| `src/app/engine.ts` | MediaPipe、坐标换算、命令执行 | 上面两个 + Three.js |

两个新模块都没有 `@ts-nocheck`，`tsc --noEmit` 直接覆盖，这也是「逐步摘掉 nocheck」的第一步。

## 三个策略

**1. 迟滞（避免临界位置反复切换）**

- `enterConf = 0.55`：低于它不进入 ACTIVE；
- `exitConf = 0.34`：低于它视为「识别质量不足」，**保持现状**而不是切走；
- 只有 label 变成 `none`，或另一个 label 的置信度过 `enterConf`，才会考虑提交。

这样光线差、手半出画导致的置信度下滑不会让树反复收放。

**2. 候选保持 + 冷却（避免过渡帧被当成命令）**

- 新 label 要连续保持 `enterHoldMs = 170 ms` 才提交（约 3 帧识别）；
- 掉回 `none` 要持续 `exitHoldMs = 150 ms` 才提交，避免单帧漏检；
- 掉回 none 后 `cooldownMs = 260 ms` 内不接受新提交，给「收树 / 再开」留出物理动作时间。

形态切换原有的 750 ms 保持与 1500 ms 命令冷却保留在引擎侧，两者叠加后的总延迟约 900 ms，
与 V2 的 4 帧(220 ms) + 750 ms ≈ 970 ms 基本持平——**没有用手势响应速度去换平滑**。

**3. One Euro（静止稳、快速跟手）**

`cutoff = minCutoff + beta · |dx|`，速度越大截止频率越高、滞后越小。

| 通道 | minCutoff | beta | 说明 |
| --- | --- | --- | --- |
| 掌心 x / y | 1.2 Hz | 2.0 | 旋转与烟花落点，要求跟手 |
| 捏合距离 | 0.9 Hz | 0.45 | 镜头缩放，宁可稳一点 |
| 掌宽 | 0.6 Hz | 0.3 | 只作尺度参考，几乎不用动 |

原来捏合还有一层 `0.78` 指数平滑，已删除：两层平滑叠加会让缩放明显滞后，现在只留 One Euro 一层。

## 断手恢复

- 手离开画面：先按 `exitHoldMs` 决定是否掉手势，再按 `lostResetMs = 220 ms` 清空全部滤波器；
- 重新出现：一定重新走 CANDIDATE，不允许凭旧状态直接 ACTIVE；
- 摄像头关闭 / 重新开启：`CTRL.reset()` 全量复位。

## 验证

**单测（8 条，`src/core/gestureController.test.ts`）**，用 60 Hz 合成轨迹回放：

| 用例 | 断言 |
| --- | --- |
| 静止 + ±0.004 高频抖动 | 不误切；输出抖动标准差 < 输入 35% |
| 真实换手势 | 提交延迟 ≤ 210 ms |
| 标签每帧来回跳 | 全程不进入 ACTIVE |
| 只闪 8 帧的手势 | 不提交 |
| 置信度掉到 0.25 | 保持原手势，不切走 |
| 断手 300 ms 后在对侧重现 | 首帧就跟到新位置（残差 < 0.01），且不立即 ACTIVE |
| 阶跃移动 | 100 ms 内跟到位 |
| 缓慢漂移 + 噪声 | 帧间跳变 < 输入步长 20%，趋势仍跟上 |

**浏览器内回放（真实打包产物）**：把同一条轨迹喂给页面里的 `debug.CTRL`，
默认参数下 `fist` 在第 11 帧（约 183 ms）提交、换 `two` 用 10 帧（约 167 ms）、
`?oe=0` 对照分别是 3 帧 / 2 帧。这条对照说明默认参数确实在压抖动而不是空转。

**假摄像头冒烟**：`--use-fake-device-for-media-stream` 起真 Chrome，
摄像头与模型都能就绪，无手时稳定在 IDLE，无报错。

**E2E**：原有 6 条 Playwright 全绿；`?oe=0` 与默认参数都能正常启动。

## 没验证的部分（如实写明）

- **没有真人手部轨迹**。以上全部是合成轨迹与假摄像头，真实的 MediaPipe 抖动幅度、
  过渡帧长度、不同光照下的 `conf` 分布都还没测。想要真正调好，需要录几段真实手势
  （静止握拳、慢速挥手、快速换手势、半出画）走一遍回放，这是下一步。
- 默认参数是按合成数据定的，`enterHoldMs` 170 ms 在真机上可能偏保守或偏激进。
- 指尖坐标（烟花落点）目前仍用原始 landmark，没有走滤波；如果真机上落点抖，再加一条通道。

## 调参入口（URL 参数，便于真机 A/B）

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `?oe=0` | 开 | 关闭滤波与保持，退回近直通 |
| `?oeHold=170` | 170 | 候选保持毫秒 |
| `?oeEnter=0.55` | 0.55 | 进入 ACTIVE 的置信度 |
| `?oeExit=0.34` | 0.34 | 质量下限 |
| `?oeBeta=2.0` | 2.0 | 掌心跟手系数 |
| `?oeMin=1.2` | 1.2 | 掌心静止截止频率（Hz） |

运行时状态：`window.__aurora.gesture()` 返回 `state / committed / candidate / confEma / config`。
